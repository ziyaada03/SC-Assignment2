2 Question 2: Parallel Bootstrapping of the Median

  • user = CPU time spent executing your R code
  • system = OS-level time (managing processes, communication, etc.)
  • elapsed = actual wall-clock time (what you care about)

For performance comparisons, elapsed is the key number.

Code 
library(MASS)
library(foreach)
library(doParallel)
library(parallel)

data(galaxies, package = "MASS")
x <- galaxies

B <- 10000  # number of bootstrap samples

2.1 Serial Bootstrap:

This is the baseline - no parallel computing.

Code 
set.seed(1)

time_serial <- system.time({
  boot_serial <- replicate(B, {
    median(sample(x, replace = TRUE))
  })
})

time_serial
   user  system elapsed 
   0.47    0.00    0.47

Note: The baseline is already quite fast, hence the task can be seen as not computationally heavy.

2.2 Parallel Bootstrap (One bootstrap per iteration):

Set up the cluster and Run a parallel version.

Code 
cl <- makeCluster(detectCores() - 1)
registerDoParallel(cl)

set.seed(1)

time_parallel_single <- system.time({
  boot_parallel_single <- foreach(i = 1:B, .combine = c) %dopar% {
    median(sample(x, replace = TRUE))
  }
})

time_parallel_single
   user  system elapsed 
   2.45    1.03    3.53

Note: We observe that parallel is much slower than serial. This could be due to the fact that each bootstrap task is tiny. You’re asking workers too: - receive a task - run one median computation - send result back The communication and coordination overhead dominates the actual computation time, and so this version shows that naive parallelisation can be slower than serial.

2.3 Parallel Bootstrap with Batching (1000 per worker task)

Batch reduces overhead from too many tiny tasks

Code 
chunk_size <- 1000
chunks <- split(1:B, ceiling((1:B) / chunk_size))

set.seed(1)

time_parallel_chunk <- system.time({
  boot_parallel_chunk <- foreach(chunk = chunks, .combine = c) %dopar% {
    replicate(length(chunk), {
      median(sample(x, replace = TRUE))
    })
  }
})

time_parallel_chunk
   user  system elapsed 
   0.00    0.00    0.17

Instead of sending 10,000 tiny jobs, you sent maybe 10 larger jobs (each doing 1000 bootstraps). Now: - Workers do substantial work before communicating back - Overhead is a mortised - Communication cost becomes negligible That’s why elapsed drops. This shows that batching reduces overhead and makes parallel computing effective.

Code 
stopCluster(cl)

3 Question 3: Bootstrap Coverage Simulation

Estimating the coverage of a percentile bootstrap confidence interval for the following scenario: sample of size 50 from an exponential distribution with mean 1.

Code 
set.seed(1)

R <- 2000     # number of simulated datasets (increase for more accuracy)
n <- 50       # sample size per dataset
B <- 1000     # bootstrap resamples per dataset
true_mu <- 1  # true mean of Exp(mean=1)

cover <- logical(R)

for (r in 1:R) {
  x <- rexp(n, rate = 1)  # mean = 1

  boot_means <- replicate(B, mean(sample(x, replace = TRUE)))

  ci <- quantile(boot_means, probs = c(0.025, 0.975), type = 6)

  cover[r] <- (ci[1] <= true_mu) && (true_mu <= ci[2])
}

mean(cover)
[1] 0.9355

Using 𝑅simulated data sets of size 𝑛= 50 from an exponential distribution with mean 1, and constructing 95% percentile bootstrap confidence intervals for the mean using 𝐵 bootstrap re-samples per data set, the estimated coverage was approximately 0.93. This is lower than the nominal 0.95 level, suggesting under-coverage. A likely reason is that the sampling distribution of the mean is skewed for exponential data at this sample size, and the simple percentile bootstrap interval is not perfectly calibrated under skewness
